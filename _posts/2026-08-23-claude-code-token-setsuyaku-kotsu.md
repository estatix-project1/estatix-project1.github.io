**この記事のまとめ(150字)**:
Claude Code のトークンを節約するコツは、「小さく切る・投げすぎない・書き直さない」の 3 原則に集約されます。実際にレートリミットに近づく主な原因は、長い文脈の再送信・不要なファイル読み込み・並列サブエージェントの多用です。この記事では $100 プラン(1 週間レートリミット)を安定して走り切るための 7 ステップを整理しました。

## 結論:節約は「モデル選び」より「渡す情報量の設計」で決まる

はじめに結論から書きます。Claude Code のトークン消費は、Sonnet か Opus かの選択よりも、**1 回のセッションでモデルにどれだけの情報を渡しているか**でほぼ決まります。

- モデル切り替えの節約幅: 感覚的にはおおむね 2〜4 倍(タスクにより変動)
- 情報量の設計次第の節約幅: 数倍〜十数倍のオーダーで動く

つまり、モデルを Sonnet に落として節約するより先に、「そもそも渡さなくてよい情報を渡していないか」を疑うほうが効きます。この記事では、その情報量を絞るための具体的な 7 ステップを紹介します。

## Claude Code のトークンを節約する 7 ステップ

### ステップ 1. まず「どこで消えているか」を 1 日測る

いきなり節約を始める前に、1 日だけ普段どおりに使ってみて、**どのタスクでトークンが多く消えているか**を体感でよいので観察してください。

- 大きなコードベース全体を読ませたとき
- 長い会話を続けて文脈が肥大化したとき
- WebSearch を連発したとき
- 同じ長文を何度も再生成させたとき

節約すべき場所を特定してから対策する順番だと、無駄な我慢がなくなります。「なんとなく Opus を避ける」だと、精度が必要な場面で困るだけで、消費はさほど減りません。

### ステップ 2. 1 タスク 1 セッションを徹底する

Claude Code のトークン消費が一番増えるのは、**1 つのセッションで複数の話題を混ぜる**ときです。会話が長くなると、モデルは過去のやり取りをすべて文脈として持ち続けるため、後半のリクエストほど「実質何もしていないのに」トークンを食います。

対策はシンプルで、話題が変わるたびにセッションを新しく開き直すことです。目安としては次の 2 点で切り替えてください。

- タスクが完了したら閉じる(次のタスクは新セッション)
- 会話が 30 往復を超えたら、要点をまとめて新セッションに移す

「まだ使えるから」と会話を継ぎ足すのが、一番静かに効いてくる浪費です。

### ステップ 3. 「関連ファイルだけ」を渡す

大規模なコードベースを丸ごと読ませたくなる場面は多いですが、そのほとんどは不要です。Claude Code は、必要になれば自分でファイルを探しに行けます。**最初に渡すべきは「作業対象のファイル 1〜3 個」だけ**にしてください。

- 悪い例: `src/` 配下を全部読ませてから「バグを直して」と依頼
- 良い例: 「`src/foo.ts` の `handleClick` 関数でクリックが 2 回発火する。修正案を出して」

前提となる情報は、必要になったタイミングで追加で渡すほうが、結果的に消費が減ります。「先に全部渡しておく」は保険のようで、実は最大級の浪費です。

### ステップ 4. Workflow と並列サブエージェントは「使わない」を基本にする

Claude Code の Workflow やサブエージェントの並列起動は強力ですが、**トークンをまとめて数倍消費する**ため、既定では使わないと決めておくのが安全です。

- サブエージェントは、各エージェントが独立した文脈を持つ = 文脈が重複してトークンが増える
- Workflow は、各ステップの入出力をチェーンで保持する = 全体の文脈が膨らむ

使いどころとしては「1 回の依頼で明らかに 10 ファイル以上を並列で触る必要がある」など、単線で組むと逆に時間がかかりすぎる場面だけに絞ってください。「試しに使ってみる」は、レートリミットを一気に食い潰す原因になります。

### ステップ 5. 長文は「再生成」ではなく「編集(Edit)」で直す

Claude Code に長い文章(記事・章原稿・README など)を書かせたあと、「もう少し違う雰囲気で書き直して」と丸ごと再生成させると、そのたびに元の長文を再送信するため、コストが 2〜3 倍に膨らみます。

節約したい場合は次の順で対応してください。

1. まず**部分編集で済むかを検討**する(「この段落だけ書き直して」「この見出しだけ言い換えて」)
2. 全体を書き直す場合は、**方向性を 1〜2 文で指定**してから依頼する(方針が定まらないと 3 回目・4 回目が発生する)
3. どうしても複数回試したいときは、Sonnet で下書き → Opus で最終仕上げ、という 2 段構えにする

「もう 1 回だけ試したい」の 1 回が、実は一番トークンを食います。編集で済むかを最初に自問してください。

### ステップ 6. WebSearch/WebFetch は「1 セッション 10 回」を上限にする

外部情報の取得は便利ですが、**1 回あたりの読み込みコストが大きい**ため、無制限に使うとすぐレートリミットに触れます。運用ルールとしては次の 2 点をお勧めします。

- 1 セッションあたり WebSearch と WebFetch の合計を 10 回以内に収める
- 検索してから同じサイトを WebFetch で開き直すのを避ける(検索結果のスニペットで足りるならそこで止める)

体感で言うと、10 回を超えたあたりから消費の伸びが急に見えるようになります。「1 回で十分な検索を 3 回投げていないか」を意識するだけで、驚くほど減ります。

### ステップ 7. モデル選択で最後に微調整する

ここまでの 6 ステップで情報量を絞ったうえで、最後にモデル選択で微調整します。個人的なおすすめは次の分担です。

- **設計・レビュー・重要な決定**: Opus(高精度が必要な場面だけに絞る)
- **日常のコード編集・下書き作成・要約**: Sonnet(体感で十分な精度)
- **軽い問い合わせ・整形作業**: Sonnet(Opus を使うほどの価値はない)

「常に Opus」ではなく、「精度が必要な瞬間だけ Opus」に切り替えるのがコツです。プラン選びの考え方は、[Claude Code の料金プラン、個人ならどれ?]({{ site.baseurl }}/ai活用/2026/08/20/claude-code-ryoukin-plan-erabikata.html) にまとめていますので、あわせてご覧ください。

## やってはいけない 3 つのアンチパターン

### アンチパターン 1. 「とりあえず全部投げる」

コードベース全部・会話履歴全部・関連しそうな資料全部を一度に投げるやり方です。モデルは全部読みますが、**そのほとんどは回答に使われません**。使われない情報でトークンを消費している状態は、純粋な浪費です。

回避策: 「今の 1 タスクに直接必要な情報は何か」を、投げる前に 1 文で答えられるかセルフチェックしてください。答えられないなら、まだ渡す情報を絞る余地があります。

### アンチパターン 2. 「気に入らないから作り直させる」を繰り返す

生成結果が気に入らないとき、方針の指示を追加せず、そのまま「もう 1 回」と再生成させる使い方です。同じ入力でもう 1 回出させても、似た結果しか返ってきません。

回避策: 気に入らない箇所を **1 文で言語化してから追加指示**を出してください。「もっと簡潔に」「専門用語を減らして」「例をもう 1 つ入れて」など、具体的な差分の指示があると、1 回で目的の出力に近づきます。

### アンチパターン 3. 「セッションを閉じない」

タスクが終わったあともセッションを開いたままにして、次のタスクを継ぎ足していく使い方です。前タスクの文脈が残り続けるため、無関係な会話でもトークンを食い続けます。

回避策: **1 タスクごとにセッションを閉じる**。閉じたセッションは記録として残るので、あとから振り返る目的でも問題ありません。

## よくある質問(FAQ)

**Q. 一番節約効果が大きいのはどのステップですか?**
A. ステップ 3(関連ファイルだけを渡す)とステップ 5(再生成ではなく編集)の 2 つが体感で最大です。この 2 つを徹底するだけで、同じ作業量でも消費が半分程度に落ちる感覚があります。逆にモデル切り替え(ステップ 7)は、慣れないうちは無理に触らないほうが安全です。

**Q. 5 時間・週次レートリミットに引っかかる主な原因は何ですか?**
A. 経験的には次の 3 つに集約されます。(1)大きなコードベースを丸ごと読ませる、(2)長文を何度も再生成させる、(3)Workflow やサブエージェントの並列起動を試す。この 3 つを避けるだけで、$100 プランでもかなりの作業量をこなせます。

**Q. 料金プランを上げれば節約は考えなくていいですか?**
A. プランを上げると余裕は増えますが、消費の癖は変わらないため、根本的な節約にはなりません。まずは無料〜個人プランのままで消費を絞る癖をつけ、それでも足りない場合にプラン増強を検討する順番がおすすめです。判断基準は [Claude Code の料金プラン、個人ならどれ?]({{ site.baseurl }}/ai活用/2026/08/20/claude-code-ryoukin-plan-erabikata.html) を参考にどうぞ。

**Q. 副業で毎日使う場合、どのくらいの消費に収まりますか?**
A. 用途によりますが、ブログ記事 1 本や小さなコード修正 1 件が 1 日の中心なら、個人プランで十分収まるケースが多いです。具体的な副業の使い方例は [Claude Code 副業の具体例]({{ site.baseurl }}/ai活用/2026/08/19/claude-code-fukugyou-gutairei.html) に整理していますので、あわせてご覧ください。

## まとめ:節約は「渡さない・書き直さない・混ぜない」で決まる

- 節約は「モデル選び」より「渡す情報量の設計」で決まる
- 1 タスク 1 セッションで、話題を混ぜない
- 関連ファイルだけを渡し、全部を先に読ませない
- Workflow・並列サブエージェントは既定では使わない
- 長文は再生成ではなく編集(Edit)で直す
- WebSearch/WebFetch は 1 セッション 10 回まで
- モデル選択は「精度が必要な瞬間だけ Opus」で微調整

トークン節約は「我慢する」ではなく「無駄な動きを削る」ことです。今日から 1 つだけ、まずは「1 タスク 1 セッション」を試してみてください。それだけで週次レートリミットまでの距離が体感で変わってきます。
