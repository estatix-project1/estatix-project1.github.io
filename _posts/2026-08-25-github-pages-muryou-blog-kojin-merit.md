**この記事のまとめ(150字)**:
GitHub Pages は、独自ドメインが不要なら費用0円で個人ブログを持てるサービスです。ただし「無料=手間がゼロ」ではなく、テーマ設定・記事の公開手順・検索エンジンへの登録リクエストを自分で回す必要があります。この記事では、実際に個人ブログを立てて8本記事を公開した実測から、メリット・デメリット・向いている人を整理します。

## 結論:「文章と Git を自分で動かせる人」には最良の無料選択肢

先に結論です。GitHub Pages で個人ブログを持つべきかは、次の3つで判断できます。

| こんな人 | GitHub Pages | note | WordPress(自前) |
|---|---|---|---|
| とにかく無料で始めたい | ◎(0円) | ◎(0円) | △(サーバー代) |
| Markdown で書きたい | ◎ | △ | ○(要プラグイン) |
| デザインを細かく変えたい | ○(HTML/CSS) | ×(制限あり) | ◎ |
| 記事のバックアップを自分で持ちたい | ◎(Gitで自動) | △(手作業) | ○(要設定) |
| 集客経路がまだ何もない | △(自力SEO) | ○(内部流入あり) | △ |
| パソコン操作の学習コストを避けたい | ×(Git必須) | ◎ | △ |

**note は「読者ゼロから書き始める人」向き、GitHub Pages は「自分の資産として文章を積み上げたい人」向き**、と考えるのが実感に近いです。

## GitHub Pages の基本(30秒で押さえる)

GitHub Pages は、GitHub というプログラマー向けのファイル置き場を、そのままWebサイトとして公開できる仕組みです。プログラミングの知識が「まったく」ゼロだと難しい場面はありますが、**Markdown で文章を書いて、それを Git というツールでアップロードするだけ**という運用に絞れば、非エンジニアでも回せます。

- URL は `https://ユーザー名.github.io/` の形になる(独自ドメインも設定可能)
- Jekyll というブログエンジンが標準で使え、記事は Markdown ファイルとして書ける
- サーバー費用・データ転送料・SSL証明書代 すべて 0 円
- 静的サイトのため、動的なコメント欄・ログイン機能などは別途工夫が必要

## メリット(実感した順に4件)

### メリット1. 費用が本当に0円で、追加課金の勧誘もない

有料のブログサービスや WordPress の自前運用と違い、**「アクセス数が増えたら課金」「独自ドメインで有料化」のような後追いの料金発生がありません**。個人ブログの多くは月間PVが数百〜数千で始まるため、その規模で費用ゼロというのは大きな安心材料です。

副業として始める場合、**初月の売上が0円だったとしても、月末に赤字にはならない**というのは想像以上に精神的なメリットになります。

### メリット2. 記事が Git に残るため、書いた文章が「消えない」

GitHub Pages で書いた記事は、すべて Git というバージョン管理ツールに保存されます。**「サービス側の都合で明日サイトが閉じる」「消したい記事を誤って復元不能に消す」といったリスクが構造的に低い**のが特徴です。

無料のブログサービスは、運営会社の方針変更・サービス終了で過去記事ごと消えるリスクを抱えています。GitHub Pages なら、たとえサービス自体が停止しても、手元の Markdown ファイルはそのまま残ります。**「文章を書き続ける前提の副業」なら、この耐久性は無視できません。**

### メリット3. 表示速度が速く、SEO 面の初期条件で不利にならない

静的なファイルを配信する仕組みなので、記事ページの表示が高速です。Google はページの表示速度を検索順位の要素として使っており、**遅い無料ブログサービスと比べたときの「入り口の不利」が発生しません**。

ただし後述しますが、速いことと**インデックス登録されること**は別問題です。速度で有利になるのは、Google に記事を認識してもらったあとの話です。

### メリット4. 記事の書式・見た目を自分の手で調整できる

Markdown だけでも書けますが、CSS ファイルを1つ足せばフォントや色を変えられます。**「サービス側が用意したテンプレートに文章を流し込む」ではなく、「自分の書式に合わせて設計する」ことができる**のが、書き手には気持ちのいい点です。

## デメリット(見落としがちな順に4件)

### デメリット1. Git の操作が最低限必要になる

これが最大のハードルです。記事を公開するには、コマンドラインで数行のコマンドを打つか、GitHub Desktop のようなソフトを使う必要があります。**「メールを送るのと同じ感覚で記事を公開したい」人には正直、向きません**。

書いた記事の反映も、ボタン1つではなく「変更を追加 → コミット → プッシュ」という3段階です。慣れれば数十秒ですが、初めの数回はここでつまずきます。

### デメリット2. 検索エンジンが自動で来てくれるわけではない

これは実際にやってみて痛感した点です。**サイトを公開したら Google が勝手に見に来て、そのうち検索結果に出る、という順序では動きません**。

サイトマップという「記事一覧のファイル」を Google Search Console に登録し、さらに記事ごとに「インデックス登録リクエスト」を送る必要があります。**この手順を踏まないと、公開しても検索対象にすらならないまま何週間も過ぎます**。

有料のブログサービスの多くは、内部からの流入(サイト内おすすめ・タグ経由)があるため、この問題が表面化しにくくなっています。GitHub Pages は完全に「外部からの検索流入だけが頼り」なので、この差は数字にはっきり出ます。

### デメリット3. コメント欄・アクセス解析・お問い合わせフォームがない

標準では、記事にコメントを書いてもらう機能・訪問者数のグラフ・お問い合わせフォームのいずれもありません。**外部サービス(Disqus・Google アナリティクス・Google フォームなど)と連携させれば実現できますが、その分手間が積み上がります**。

副業として始めるなら、最初はコメント欄なし・お問い合わせは無効でも問題ありません。ただし「読者との交流が第一目的」ならプラットフォームを間違えないほうがよいです。

### デメリット4. デザインを凝ろうとした瞬間に沼になる

「もう少しおしゃれにしたい」と思って CSS を触り始めると、**Web デザインの学習に時間を取られて肝心の記事が書けなくなる**リスクがあります。

無料テーマ(minima・Cayman など)のまま運用し、フォントと色だけ変える程度に留めるのが、副業として続ける現実解です。

## 実測データ:8記事公開して分かった落とし穴

自分で GitHub Pages に個人ブログを立て、19日で8記事を公開してみた実測を出します。

- **表示速度**: どの記事も1秒未満で表示。この点は満足
- **月額費用**: 0円(独自ドメインも取得していないため)
- **記事公開までの手順**: Markdown 作成 → Git コミット → Git プッシュ → 約45秒後にサイトに反映
- **Google の検索結果への表示**: 19日経過時点で、**8記事中インデックス登録されていたのは1ページのみ**。しかも表示回数は14日間で1回だけ

最後の1点は、想像より深刻でした。**「記事を書き続ければそのうち Google が来る」というのは、既に運営歴のあるサイトでの話**です。新規ドメインの場合、記事を公開したその場でインデックス登録のリクエストを送らないと、何ヶ月も気づかれないまま埋もれます。

対処として、次の運用に変えました。

1. 記事を公開する
2. その場でサイトの表示を確認(URL を実際に開いて開けるかを見る)
3. Search Console でその記事のURLを検査し、「インデックス登録をリクエスト」ボタンを押す

**この3手を踏まないと、GitHub Pages の無料ブログは検索エンジンに認知されない状態が続きます**。「無料で使える」ことと「無料で集客できる」ことは別問題だと理解しておいたほうが安全です。

## こんな人には GitHub Pages が向いています

- 文章を「自分の資産として」積み上げたい人(記事が Git に残る)
- 表示速度・費用・デザインの自由度で妥協したくない人
- コマンドライン操作を1度覚えれば、あとは長く回せる人
- 副業として、初期費用0円で3ヶ月〜半年のスパンで結果を見たい人

## こんな人には向かないかもしれません

- コマンドライン操作を覚える時間がない人 → note が現実解
- 開始1〜2ヶ月で流入が欲しい人 → プラットフォーム側の内部流入がある note か Qiita
- 読者との双方向の交流が最重要目的の人 → note か SNS 併用ブログサービス
- デザインを本格的に自由化したい人 → WordPress 自前運用

## よくある質問

**Q. プログラミングは本当に不要ですか?**
A. Markdown で記事を書くだけなら不要ですが、公開する際に Git のコマンド(または GitHub Desktop の操作)は必要です。「プログラミング」ではないものの、**キーボードから決まったコマンドを打つ作業**は避けられません。最初の数回はつまずくと考えておいてください。

**Q. 独自ドメインは必要ですか?**
A. 個人ブログのスタート段階では不要です。`ユーザー名.github.io` のURLでも十分機能します。「事業として本気で伸ばす」段階になってから、独自ドメイン(年間1,000〜2,000円程度)を検討すれば十分です。

**Q. AIエージェントに記事の下書きを書かせてもよいですか?**
A. 品質管理を人間側で行うなら、有効な手段です。AI に丸投げすると事実誤認や画一的な構成になりがちなので、**構成案を人間が決めて、本文の初稿を AI に任せ、事実確認と語尾調整を人間が行う**という分担が現実的です。具体的な手順は [Claude Code の始め方(非エンジニア向け)]({{ site.baseurl }}/2026/08/17/claude-code-hajimekata-hi-engineer/) にまとめています。

**Q. 収益化はできますか?**
A. アフィリエイトリンクや Amazon 商品リンクは問題なく貼れます。ただし GitHub Pages 側の規約上、**アダルト・暴力的・違法な内容の掲載は禁止**されているため、扱う商材ジャンルには気をつけてください。

**Q. 途中で note や WordPress に引っ越せますか?**
A. Markdown のファイルが手元に残っているため、引っ越し自体は可能です。ただし記事の URL は変わるため、それまでに獲得した検索順位・被リンクはリセットされます。**始めるときに「3ヶ月やってから判断する」など期限を決めておく**と、無駄な移行を避けられます。

## まとめ:0円で始められる代わりに、動く手間はゼロではない

- 費用は本当に0円で、追加課金の勧誘もない
- 記事が Git に残るため、書いた文章が消えるリスクが低い
- 検索エンジンには自動で認知されない(能動的にリクエストが必要)
- コマンドライン操作を1度覚える必要がある

「無料 = 手間ゼロ」ではなく、**「無料の代わりに、通常はサービス側が肩代わりする作業を自分で回す」**のが GitHub Pages の実態です。副業として3ヶ月〜半年の時間軸で取り組める人にとっては、費用面・耐久性面で最良の選択肢になります。
