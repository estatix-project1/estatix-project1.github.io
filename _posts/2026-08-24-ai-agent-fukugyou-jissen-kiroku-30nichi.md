## 20〜30日目に起きたこと(日別)

### 20〜23日目(8月25〜28日):ブログの型を4つに固める

書籍執筆を終えた後、ブログのテンプレートを4型そろえました。**「毎日書く」より「毎日型を再利用する」ほうが、疲れずに走れるという実感があります。**

- 20日目: A9(比較型・メリット/デメリット表)
- 21日目: A10(物販導線型・原因分類→対策→買うなら順)
- 22日目: A11(物販導線型・第2本 / 同じ型を別テーマで回転)
- 23日目: A12(判断基準+公式リンク誘導型 / リスキリング需要)

書きながら気づいたのは、**同じ型を2〜3回転させると原稿の骨子作成が消える**ことです。20日目で作った型を21日目に流し込むだけで、22日目には30分早く書き上がっていました。

### 24〜25日目(8月29〜30日):インデックスされない真因の切り分け

Google Search Consoleに入り、「なぜ流入がゼロなのか」を切り分けました。表面的にはサイトマップが「取得できませんでした」になっていましたが、**真因は別**でした。

- URL検査で確認したところ、**Googlebotが2026年8月9日以降サイトに来ていない**(20日間クロールなし)
- 判定は「クロールを許可: はい / インデックス登録を許可: はい」= **技術的な障害はゼロ**
- つまり単に**サイトが発見されていない**だけで、meta タグや robots.txt を触っても解決しない

打ち手は「外部からの発見経路を作る」の一点に絞りました。noteに被リンク導線用の記事を書き始めたのがここです。

### 26〜30日目(8月31〜9月4日):被リンク導線と型の横展開

noteに被リンク導線用の記事を**合計5本**公開しました。各記事にブログ5〜7本のリンクを埋め込み、延べ35本の外部リンクをブログに向けた形です。同時にブログもクラスタC(判断基準+最小構成型)・クラスタB(物販導線型)を回転させ、A18まで到達しています。

- 26日目: A14(Notion 家計簿 / クラスタC回転2)
- 27日目: A15(音声入力 議事録 / クラスタC回転3)
- 28日目: A16(Google カレンダー 家族共有 / クラスタC回転4=**型として完全に確立**)
- 29日目: A17(静音マウス 会議用 / クラスタB回転4)
- 30日目: A18(Claude Code CLAUDE.md 書き方 / クラスタA機能単位・第8本)

## 30日で分かったこと(5件)

19日目に書いた4点は、いずれも30日目でも変わっていません。加えて次の5点が新たに分かりました。

1. **1ヶ月では検索流入は動かない。** ブログ18本を公開しても、Google認識は1本のまま。新規ドメインは「発見されるまでの時間」が本質的に長い
2. **サイト側をいくら直しても、クロールされないと意味がない。** meta・sitemap・robots.txt はすべて正常でも、Googlebotが来なければゼロは動かない
3. **打ち手は「外部からの発見経路」の一点に絞る。** noteの被リンク導線・GitHubリポジトリのhomepage欄・ソーシャルからの流入経路づくりが、記事本数を増やすより優先度が高い
4. **同じ型を4回転させるとテンプレは完全に固まる。** クラスタC(判断基準+最小構成型)は4本目のA16で骨子作成が消え、以降は執筆時間が短縮された
5. **数字が取れない期間は「切り分け」に投資する。** 売上0が続く1ヶ月でも、「なぜ0か」を切り分ける作業は進められる。ここを疎かにすると、判定期限が来たときに「棄却も継続も判断できない」状態になる

## うまくいかなかったこと(追加3件 / 19日目分と合わせて計6件)

### 失敗4. Google Search Console と KDP レポートの自動取得が権限拒否で止まった

自動実行環境から Chrome を経由して Search Console と KDP の数字を取ろうとしましたが、**8日連続で `Permission denied by user` に阻まれ**、数字が全く更新できていません。対話セッションからは通ることを確認済みなので、次の対話セッションで一括取得する運用に切り替えました。

**教訓**: 「自動取得が失敗しても、次のセッションで手動確認する」というエスカレーション条件をあらかじめ組み込んでおかないと、失敗が常態化して事業判断が止まります。

### 失敗5. インデックス登録リクエストを「後回し」にしていた

記事を書いた当日にインデックス登録リクエストを出すべきでしたが、当初は「後でまとめて出す」運用にしていました。結果として、記事7本を書いた時点でリクエスト済みは0本という状態を作ってしまいました。

**教訓**: 記事を公開したら、その場でリクエストする。「まとめて後で」は事実上「やらない」と同義でした。

### 失敗6. 「commit メッセージに書いてある = 実装されている」を信じてしまった

自動化スクリプトの改修時、コミットメッセージに「機能追加完了」と書いたものの、実際にはロジックが実装されていない箇所が2件ありました(1件は発覚まで2日、もう1件は3日)。**メッセージは主張であって実装ではありません。**

**教訓**: API を経由する処理は、実装本体を grep して該当行の存在まで確認する。人間の書いた要約より、動くコードのほうが信頼できます。

## 判定期限までの残り13日でやること

Kindle書籍の30日計測は9月17日で締めます。残り13日で確認するのは次の3点です。

- **noteの被リンク経由でGooglebotが来るか。** 5本の外部リンクが「発見の経路」として機能するかを、URL検査の「前回のクロール日」で追う
- **Kindle注文数の実測。** 対話セッションから KDP レポートを取得し、注文0が継続しているかを日次で記録
- **A19以降の記事を、既存4型の再利用だけで書き続けられるか。** 新テンプレを増やすより、既存型の運用効率を上げるフェーズへ

30日目でH-001(初月10冊)の判定期限に近づいていますが、**現在の情報では棄却でも成立でもなく、単に「数字が取れていない」状態**です。判定期限までに数字を取ることが、次の最重要タスクになります。

## よくある質問

**Q. 30日で0円なら、AIエージェントに任せる意味はありましたか?**
A. 「稼ぐ」の意味では、この1ヶ月にはありませんでした。ただし「同じ品質で30日間、毎日1本記事を書き続ける」ことは、人間側だけでは高い確率で失敗します。**在庫を積むフェーズを、疲弊せず走りきれた点には意味があった**と考えています。売上として意味があったかは、次の30日の数字を見てから判断します。

**Q. 1ヶ月やっても検索流入がゼロなのは普通ですか?**
A. 新規ドメイン(=被リンクゼロで作ったばかりのサイト)では珍しくありません。Googleが記事を認識するまでに数週間〜数ヶ月かかることがあり、この期間は記事の質と関係なくゼロが続きます。**「まだ発見されていない」フェーズと、「発見されたが評価が低い」フェーズを混同しないことが重要**です。

**Q. 費用は本当に0円のままですか?**
A. はい、追加費用は0円のままです。ブログはGitHub Pages、出版はAmazon KDP、アフィリエイトはA8.net、被リンク導線はnote、いずれも登録・利用は無料です。ただしAIツール自体の月額料金は別途かかっています(本記事では検証対象外)。

**Q. 同じことを始めるなら、30日目までに何を必ず決めておくべきですか?**
A. 「判定期限」と「棄却条件」の2つです。今回の設計では「30日で10冊未満なら棄却」を先に決めていたおかげで、0円の1ヶ月を「失敗」ではなく「情報を集めた期間」として整理できています。具体的な始め方は [Claude Code の始め方(非エンジニア向け)]({{ site.baseurl }}/2026/08/17/claude-code-hajimekata-hi-engineer/) にまとめています。
